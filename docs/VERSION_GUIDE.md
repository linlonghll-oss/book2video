# 文档版本管理规范（Version Guide）

> 本文件是 book2video 项目所有 PRD、技术设计文档、测试文档的版本管理唯一规范。
> 知识库管理员负责维护此规范并执行版本控制流程。

---

## 1. 目录结构

```
docs/
  prd/              — 产品需求文档（PRD）
  tech-design/      — 技术设计文档（TDD）
  test/             — 测试文档（测试报告、测试计划、用例文档）
  _archive/         — 历史归档版本（被 supersede 的旧版本）
  _REGISTRY.md      — 文档注册表（所有文档的索引和版本追踪）
  VERSION_GUIDE.md  — 本文件
```

---

## 2. 文档命名规范

| 文档类型 | 命名格式 | 示例 |
|----------|----------|------|
| PRD | `PRD-[功能名].md` | `PRD-协作功能.md` |
| 技术设计 | `TDD-[模块名].md` | `TDD-用户系统.md` |
| 测试文档 | `TEST-[测试范围].md` | `TEST-全量Bug测试.md` |

- 文件名**不含版本号**，当前活跃版本始终使用无版本号文件名。
- 归档版本放入 `_archive/`，文件名追加版本后缀：`PRD-协作功能-v1.0.md`。

---

## 3. 版本号规则

采用 **语义化版本（SemVer）** 的文档变体：

```
vMAJOR.MINOR
```

| 版本变更 | 触发条件 | 示例 |
|----------|----------|------|
| **MAJOR** (v2.0) | 文档描述的需求/方案发生方向性变更、大规模重写、不兼容前后版本 | 需求从"邮箱注册"改为"手机号注册" |
| **MINOR** (v1.1) | 新增章节、补充需求项、修改细节但整体方向不变 | 新增 P1 需求、调整指标目标值 |
| **Patch 标记** | 仅修改错别字、格式、措辞——不升版本号，直接在原文修改 | 修正表格格式 |

> 草稿阶段（Draft 状态）内的修改不升版本号。版本号在状态从 Draft → Review 时正式冻结。

---

## 4. 文档状态流转

```
Draft → Review → Approved → Published → Superseded
                                                    ↘ Archived
```

| 状态 | 含义 | 谁可以操作 |
|------|------|-----------|
| **Draft** | 撰写中，内容可随时变更 | 文档作者 |
| **Review** | 提交评审，版本号冻结，仅接受评审意见修改 | 评审人 |
| **Approved** | 评审通过，可作为开发依据 | 技术负责人/PM |
| **Published** | 正式发布，开发团队按此执行 | 知识库管理员 |
| **Superseded** | 被新版本取代，不再活跃 | 知识库管理员 |
| **Archived** | 归档至 `_archive/`，保留可追溯 | 知识库管理员 |

---

## 5. 文档头部元信息（必填）

每份文档的**第一个表格**必须包含以下字段：

```markdown
| 字段 | 内容 |
|------|------|
| **文档版本** | v1.0 |
| **状态** | Draft |
| **作者** | 姓名/角色 |
| **创建日期** | YYYY-MM-DD |
| **最后更新** | YYYY-MM-DD |
| **关联项目** | book2video |
| **关联文档** | （如有依赖/关联的其他文档，填写文件名） |
```

---

## 6. 变更记录（必填）

每份文档末尾必须包含变更记录表：

```markdown
## 变更记录

| 日期 | 版本 | 变更内容 | 作者 |
|------|------|----------|------|
| 2026-07-29 | v1.0 | 初始版本 | PM |
| 2026-07-30 | v1.1 | 新增 P1-6 需求项 | PM |
```

---

## 7. 版本发布流程

1. **修改文档** → 更新内容，更新「最后更新」日期。
2. **判断版本变更** → MAJOR 还是 MINOR？
3. **归档旧版本** → 将当前文件复制到 `_archive/`，追加版本后缀。
4. **更新注册表** → 在 `_REGISTRY.md` 中更新版本号、状态、变更摘要。
5. **记录变更** → 在文档末尾的变更记录表追加一行。
6. **通知相关方** → 告知开发/测试团队文档已更新。

---

## 8. 注册表维护规则

- `_REGISTRY.md` 是所有文档的**单一事实源**。
- 任何文档的创建、版本升级、状态变更、归档操作，必须**同步更新注册表**。
- 知识库管理员每周核查一次注册表与实际文件的一致性。
