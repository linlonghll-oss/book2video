## 1. 问题陈述

book2video 目前是一个纯粹的**单用户工具**——没有用户系统，所有数据（笔记、文件夹、素材、视频）存储在本地 SQLite 中，任何人打开应用都能看到所有内容，无法区分"我的"和"别人的"。

这在以下场景中变成了直接阻碍：

- **读书会 / 共读小组**：一群人一起读一本书，各自写了笔记，希望共享素材池（AI 配图、TTS 语音），避免重复生成、节省 API 费用。
- **内容团队**：运营团队 3-5 人协作产出视频/PPT/图文，需要共享笔记草稿、分工剪辑、统一管理输出物。
- **教育场景**：老师布置读书笔记作业，学生提交后老师统一审阅、生成班级视频合集。

**不做这个功能的代价**：
- 用户增长遇到天花板——单用户工具的传播靠口碑，而协作工具的传播靠"邀请队友"（自带裂变）。
- 素材和 API 调用大量重复浪费——同一本书的配图 5 个人各生成一遍。
- 竞品（如剪映企业版、Canva Teams）已经在协作上发力，book2video 如果持续单机，难以上升为团队工具。

**证据来源**：基于产品定位推断（读书笔记 → 视频是天然的内容创作场景，而内容创作往往需要团队协作）。正式启动前建议通过用户访谈验证（见第 7 节开放问题）。

## 2. 目标

### 用户目标
- 用户能创建团队工作空间，邀请成员加入，在一个空间内共享笔记和素材。
- 团队成员能查看、编辑共享笔记，避免重复上传和重复生成素材。
- 团队管理员能控制成员的访问权限（查看 / 编辑 / 管理）。

### 业务目标
- 协作功能上线 3 个月内，**团队空间创建数 ≥ 500**。
- 协作空间用户的 **7 日留存率比单用户高 15%**（协作带来的粘性）。
- 为后续的付费团队版（按席位收费）奠定基础。

### 产品目标（可衡量）
- 从「无用户系统」平滑升级为「有用户系统」，现有本地数据不丢失。
- 支持 2-20 人的小团队协作，不要求支持百人以上大组织（那是 V2）。
- 协作冲突率（两人同时编辑同一笔记）上线第一个月 <5%。

## 3. 非目标（Non-Goals）

| 非目标 | 原因 |
|--------|------|
| **实时协同编辑**（类似 Google Docs 的多人同时打字） | 技术复杂度极高（OT/CRDT），ROI 不匹配当前阶段。V1 采用「锁定 + 覆盖提醒」的简化方案 |
| **评论 / 批注功能** | 有价值但会显著增加 UI 复杂度，独立作为后续功能迭代 |
| **版本历史 / Diff 对比** | Script 表已有 version 字段，但全量版本管理需求不够强，V2 考虑 |
| **SSO / OAuth 企业登录** | 当前目标用户是个体/小团队，邮箱注册 + 密码足够 |
| **计费 / 订阅系统** | 协作功能 V1 免费，商业模式验证后再做 |
| **百人以上大团队** | 架构上不针对大组织优化（如 RBAC、部门层级），保持简单 |

## 4. 用户故事

### 4.1 用户与空间管理

**US-1**：作为一个新用户，我希望**用邮箱注册账号并登录**，以便我的数据有归属、不会被别人看到或修改。

**US-2**：作为一个已登录用户，我希望**创建一个工作空间（Workspace）**，以便我和我的团队有一个共享的内容区域。

**US-3**：作为空间创建者（Owner），我希望**通过邮箱/链接邀请成员加入**，以便我的团队成员能一起协作。

**US-4**：作为一个被邀请者，我希望**接受邀请后自动加入空间**，以便我不需要手动输入任何代码或密码。

**US-5**：作为空间 Owner，我希望**设置每个成员的权限为「编辑者」或「仅查看」**，以便控制谁能修改内容。

### 4.2 笔记协作

**US-6**：作为一个协作空间成员，我希望**看到空间内所有人创建的笔记和文件夹**，以便了解团队的整体进度。

**US-7**：作为一个编辑者，我希望**打开别人创建的笔记进行编辑**，以便我可以帮忙润色文案或调整脚本参数。

**US-8**：作为一个编辑者，当我在编辑笔记时，我希望**其他人看到一个「编辑中」的状态提示**，以免两人同时修改导致冲突。

**US-9**：作为一个编辑者，当我保存笔记时如果发现已被他人修改，我希望**收到冲突提示，并可以选择覆盖或放弃**，以免不小心覆盖别人的工作。

**US-10**：作为一个编辑者，我希望**查看每篇笔记的「创建者」和「最后修改者」信息**，以便了解内容来源和变更责任。

### 4.3 素材共享

**US-11**：作为一个编辑者，当我打开一篇已有配图/语音/字幕的笔记时，我希望**直接复用这些素材**而不需要重新生成，以便节省 API 费用和时间。

**US-12**：作为一个编辑者，当我修改了脚本并重新生成素材时，我希望**不影响别人正在使用的旧素材**（新素材作为新版本追加），以便团队成员的工作不被中断。

### 4.4 个人空间

**US-13**：作为一个用户，我希望**保留一个「个人空间」用于我的私人笔记**，与团队空间完全隔离，以便我的私人创作不受团队干扰。

### 4.5 边缘情况

**US-14**：作为一个 Owner，当我移除一个成员时，该成员创建的笔记**保留在空间内**（不随成员离开而删除），但该成员失去访问权限。

**US-15**：作为一个被移除的成员，我希望收到明确的通知，且被移除前我创建的内容归属清晰。

**US-16**：当空间只剩最后一个人时，空间不自动删除，但该用户可以选择归档或删除空间。

## 5. 需求分级

### P0 — 必须上线（缺了就不是协作）

| # | 需求 | 说明 |
|---|------|------|
| P0-1 | **用户注册 / 登录** | 邮箱 + 密码注册，JWT Token 认证。注册后自动创建默认「个人空间」 |
| P0-2 | **工作空间创建与管理** | 任何登录用户可创建空间，自动成为 Owner。Owner 可修改空间名称、删除空间 |
| P0-3 | **成员邀请与权限** | Owner 通过邮箱邀请。支持两种角色：Editor（读写）和 Viewer（只读） |
| P0-4 | **空间内笔记共享** | 空间内所有成员可见空间内全部笔记和文件夹（按空间隔离） |
| P0-5 | **笔记编辑权限控制** | Viewer 只能看不能改；Editor 可编辑任意笔记（简化协作模型，不做笔记级权限） |
| P0-6 | **素材复用** | 同一笔记的已有 Material（配图/音频/字幕等）对所有空间成员可见可用，不重复生成 |
| P0-7 | **数据迁移** | 现有本地数据自动归属到升级后创建的第一个用户（或提供导入选项） |
| P0-8 | **笔记元信息展示** | 显示创建者、最后修改者、最后修改时间 |

### P1 — 应该尽快做（显著改善体验）

| # | 需求 | 说明 |
|---|------|------|
| P1-1 | **编辑锁定机制** | 用户打开笔记编辑时，前端请求「编辑锁」，其他用户看到「xxx 正在编辑」提示。锁在用户关闭编辑页或 5 分钟无操作后自动释放 |
| P1-2 | **冲突检测与提醒** | 保存时检测 `updated_at` 是否比自己打开时更新，若已更新则弹窗提示「已被他人修改，是否覆盖？」 |
| P1-3 | **邀请链接** | 生成一次性/有时效的邀请链接，方便通过微信/飞书等 IM 分享 |
| P1-4 | **空间内搜索** | 按标题搜索空间内所有笔记 |
| P1-5 | **成员列表管理** | 查看空间内所有成员及其角色，Owner 可修改角色或移除成员 |

### P2 — 未来考虑（架构上先留好口子）

| # | 需求 | 说明 |
|---|------|------|
| P2-1 | **笔记级权限** | 在空间内对特定文件夹/笔记设置更细粒度的权限（如某篇笔记设为「仅 Owner 可编辑」） |
| P2-2 | **操作日志** | 空间内显示「谁在什么时候做了什么」（谁生成了视频、谁修改了脚本） |
| P2-3 | **素材去重** | 系统级检测相同 prompt 的 AI 图片生成请求，自动复用已有素材（跨笔记、跨空间可配） |
| P2-4 | **实时通知** | WebSocket 推送「xxx 邀请你加入空间」「xxx 完成了视频生成」等通知 |
| P2-5 | **视频协作评论** | 对最终生成的视频进行时间轴评论（类似 Frame.io） |

## 6. 成功指标

### 北极星指标
**协作活跃空间数**：过去 7 天内，至少 2 名成员进行了编辑操作的空间数量。
> 这个指标直接衡量"协作有没有真正发生"，而不是"空间创建了就放着不用"。

### 驱动指标（Leading Indicators）

| 指标 | 目标 | 测量方式 |
|------|------|----------|
| 注册转化率 | 首页访问 → 注册完成 > 40% | 前端埋点 |
| 空间创建率 | 注册用户中创建空间的比例 > 25% | 数据库查询 |
| 邀请转化率 | 发送邀请 → 接受邀请 > 60% | 邀请链接埋点 |
| 素材复用率 | 协作空间内，被复用的 Material 数 / 总 Material 数 > 30% | 数据库查询 |
| 编辑冲突率 | 冲突提示弹出次数 / 总编辑保存次数 < 5% | 前端埋点 |

### 滞后指标（Lagging Indicators）

| 指标 | 目标 | 评估时间 |
|------|------|----------|
| 7 日留存（协作用户 vs 单用户） | 协作用户留存 > 单用户 + 15% | 上线后 30 天 |
| 人均生成视频数（协作 vs 单人） | 协作用户人均生成数 > 单用户 × 1.3 | 上线后 60 天 |
| API 费用节省 | 素材复用带来的 API 调用减少 > 20% | 上线后 90 天 |

## 8. 时间线考量

### 依赖关系
```
用户系统（P0-1）→ 工作空间（P0-2, P0-3）→ 笔记共享（P0-4~P0-8）→ 协作增强（P1-1~P1-3）
                                                                        ↘ 个人空间（US-13，可与笔记共享并行）
```

### 建议分期

**Phase 1（MVP，约 3 周）**：P0 全量交付
- 用户注册/登录
- 工作空间创建、成员邀请
- 空间内笔记共享、权限控制
- 素材复用
- 数据迁移方案

**Phase 2（增强，约 2 周）**：P1 交付
- 编辑锁定 + 冲突检测
- 邀请链接
- 空间内搜索

**Phase 3（后续）**：P2 按优先级排入后续路线图

### 硬性依赖
- 需要一个服务端部署环境（本地 SQLite → 中心化数据库），这是 Phase 1 的前提条件
- 如果需要发送邀请邮件，需要接入邮件服务（如 SendGrid / Resend）

## 9. 附录：数据模型变更提案

### 新增表

```sql
-- 用户表
CREATE TABLE users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    email VARCHAR(255) NOT NULL UNIQUE,
    password_hash VARCHAR(255) NOT NULL,
    display_name VARCHAR(100),
    avatar_url VARCHAR(512),
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 工作空间表
CREATE TABLE workspaces (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name VARCHAR(255) NOT NULL,
    owner_id INTEGER NOT NULL REFERENCES users(id),
    invite_code VARCHAR(20) UNIQUE,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 工作空间成员表
CREATE TABLE workspace_members (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    workspace_id INTEGER NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
    user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    role VARCHAR(20) NOT NULL DEFAULT 'editor',  -- 'owner' | 'editor' | 'viewer'
    joined_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(workspace_id, user_id)
);
```

### 变更现有表

```sql
-- Note 表新增字段
ALTER TABLE notes ADD COLUMN workspace_id INTEGER REFERENCES workspaces(id);
ALTER TABLE notes ADD COLUMN created_by INTEGER REFERENCES users(id);
ALTER TABLE notes ADD COLUMN updated_by INTEGER REFERENCES users(id);

-- Folder 表新增字段
ALTER TABLE folders ADD COLUMN workspace_id INTEGER REFERENCES workspaces(id);

-- 为每个用户自动创建「个人空间」对应的 workspace_id
-- 个人空间是一种特殊的 workspace，workspace_members 中只有该用户一人，role=owner
```

### 前端状态管理变更

- 新增 `authStore`：管理 JWT Token、当前用户信息、登录状态
- 新增 `workspaceStore`：管理当前活跃 workspace、成员列表
- 修改 `noteStore` / `folderStore`：所有 API 请求携带 `workspace_id` 上下文和 Authorization header
- 所有 API 请求添加拦截器：401 时自动跳转登录页
