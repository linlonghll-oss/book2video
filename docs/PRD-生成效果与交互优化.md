## 1. 现状诊断

经代码审查，当前系统在生成效果和交互体验上存在以下具体问题：

### 1.1 生成效果问题

| 环节 | 问题 | 根因 | 严重性 |
|------|------|------|--------|
| **脚本质量** | 情绪标签只有 3 种（neutral/positive/inspiring），无法覆盖「深沉」「怀旧」「紧迫」等常见读书内容情绪 | `_validate_script` 中硬编码了白名单 | P1 |
| **脚本质量** | 50%+ 的情况 LLM 返回的 JSON 不标准，解析失败后静默降级为 dry-run | 不同模型的 JSON 输出能力差异大，但用同一套解析逻辑 | P0 |
| **配图 Prompt** | 先调用 LLM 翻译成英文 prompt，链条长，失败后回退到纯模板拼接的弱 prompt | `_generate_image_prompts_llm` 失败时 fallback 到 `_build_visual_prompt`，后者只是「风格前缀 + visual_hint + 情绪后缀」的简单拼接 | P0 |
| **配图风格** | 只有 5 种风格预设（realistic/comic/illustration/anime/watercolor），缺少「中国风」「手绘」「极简」等更适合读书内容的风格 | `IMAGE_STYLE_MAP` 硬编码 | P1 |
| **配图失败** | 图片生成失败时静默跳过，导致视频缺段，用户看到一支不完整的视频 | `_generate_ai_image` 返回 None 后，`generate_materials` 不做任何补救 | P1 |
| **TTS 质量** | 只支持 edge-tts（免费但音色有限、依赖微软服务不稳定），没有高质量替代方案 | composer.py 中 `_generate_tts_audio` 只调 edge-tts | P1 |
| **字幕可读性** | 纯白字无背景条，浅色画面上看不清；断句逻辑过于粗暴 | `_render_subtitle_png` 没有半透明背景；`_split_text_to_phases` 遇到无标点长句就一刀切 | P0 |
| **Ken Burns** | 缩放幅度 1.08x，肉眼几乎看不到动态效果 | `KEN_BURNS_ZOOM = 1.08` 是固定常量 | P2 |
| **淡入淡出** | 固定 1 秒，用于 3-5 秒的短段落显得过长 | `FADE_DURATION = 1.0` 不区分段长 | P2 |

### 1.2 交互复杂度问题

| 问题 | 现状 | 影响 |
|------|------|------|
| **步骤过多** | 7 个独立步骤（优化文案→优化脚本→配图→TTS→字幕→分段视频→合成），每步都要手动点击 | 做一支视频要点 7 次按钮，每次等 10-60 秒 |
| **参数选择重复** | 每步都要选模型/风格/音色，即使和上次一样 | 每次做视频都是一次「重新配置」而非「标准化生产」 |
| **默认值不友好** | 默认不是用户上次成功使用的配置 | 增加操作记忆负担 |
| **错误不透明** | 静默失败的 fallback 太多，用户不知道哪里出问题 | 「为什么这次视频效果不如上次」无法追溯 |
| **一键生成不够智能** | 一键生成只是顺序执行 7 步，中间任意一步失败后整条链失效 | 让人不敢用 |

## 2. 优化目标

### 2.1 用户体验目标

| 指标 | 当前（估计） | 目标 |
|------|------------|------|
| 笔记 → 可观看视频的完成率 | ~60%（中间某步失败导致放弃） | ≥ 90% |
| 操作步骤数（从笔记到视频） | 7 步 × N 次参数选择 | **2 步**（输入笔记 → 点击生成） |
| 无干预生成成功率 | ~50%（依赖所有环节都成功） | ≥ 85%（智能恢复 + fallback 补位） |
| 用户对视频效果的满意度 | — | NPS ≥ 30 |

### 2.2 非目标

- 不是重写整个 pipeline，是优化现有链路中的关键瓶颈
- 不增加新的 AI 能力（如 AI 写脚本），聚焦当前环节的质量和可靠性
- 不做实时预览（那是 V2 的事）
- 不做视频编辑功能（裁切、调速等）

---

## 3. 优化方案

### 方案总览

两个维度并行推进：

**A. 链路健壮性（减少失败）** → 让生成结果「稳定可预期」
**B. 效果提升（做好默认值）** → 让生成结果「好看」

交互优化在此基础上：有了稳定的输出质量，才能简化操作流程——否则少点几步但出来的东西没法看，用户一样不满意。

## 4. 效果提升方案

### 4.1 P0：脚本生成稳定性（optimizer.py）

**问题**：不同模型 JSON 输出能力差异大，经常解析失败。

**方案**：

1. **改为 Markdown 结构化输出**：不再要求 LLM 输出纯 JSON（这对小模型很困难），改为要求输出带标记的 Markdown，如：

```
---SEGMENT---
text: 旁白文案
visual_hint: 画面建议  
emotion: neutral
duration: 6
---SEGMENT---
text: 下一段旁白
visual_hint: 下一段画面
emotion: positive
duration: 5
```

解析时用 `---SEGMENT---` 做分割，每段内用 `key: value` 提取。这比纯 JSON 解析鲁棒得多。

2. **扩展情绪标签**：从 3 种扩展到 6 种（增加 reflective / dramatic / calm）

3. **智能长度约束**：在系统 prompt 中明确「每段 text 控制在 15-25 字（中文口语速度约 4 字/秒，适合 4-6 秒的旁白）」，而不是模糊的 50-120 字。

### 4.2 P0：配图 Prompt 质量（material_gen.py）

**问题**：两段式（LLM → 图片模型）链条太长，fallback 的 prompt 太弱。

**方案**：

1. **合并为一步**：在 optimizer.py 生成脚本时，直接要求每段输出一个英文 prompt 字段，不再单独调一次 LLM：

```markdown
---SEGMENT---
text: 旁白文案
image_prompt: A warm reading nook with afternoon sunlight, book open on wooden table, cat sleeping nearby, cozy atmosphere, 16:9 cinematic composition, soft natural lighting
emotion: calm
duration: 6
```

2. **Prompt 增强模板**：不管 prompt 来源是 LLM 还是 visual_hint，都在发送给图片模型前统一追加质量后缀：

```python
QUALITY_BOOST = "masterpiece, best quality, 4k, cinematic lighting, sharp focus, professional photography"
NEGATIVE = "text, watermark, logo, signature, low quality, blurry, distorted, deformed"
```

3. **Fallback 到位**：`_build_visual_prompt` 从简单拼接升级为更结构化的 prompt 构建，加入「构图描述 + 光线 + 色调」三个维度。

### 4.3 P1：图片风格扩展

新增 5 种更适合读书/知识内容的风格：

| 风格 ID | 中文名 | Prompt 后缀 |
|---------|--------|------------|
| `chinese-ink` | 水墨中国风 | Chinese ink wash painting, elegant brushstrokes, traditional art style |
| `minimalist` | 极简黑白 | Minimalist black and white photography, clean lines, negative space, high contrast |
| `sketch` | 手绘素描 | Hand-drawn pencil sketch, artistic rough lines, sketchbook aesthetic |
| `film-grain` | 胶片质感 | Film grain, vintage photography, warm tones, nostalgic feel |
| `editorial` | 杂志插画 | Editorial illustration, The New Yorker style, sophisticated color palette |

### 4.4 P1：字幕可读性（composer.py）

**方案**：

在 `_render_subtitle_png` 中增加半透明黑色背景条：

```python
# 渲染背景条
bar_y_start = bar_y - _SUB_BAR_PADDING
bar_width = video_w  # 全宽背景条
draw.rectangle(
    [0, bar_y_start, bar_width, bar_y + bar_h + _SUB_BAR_PADDING],
    fill=(0, 0, 0, 128)  # 50% 透明黑色
)
```

文字在背景条上居中显示，白色字体。

### 4.5 P1：TTS 引擎扩展

在 edge-tts 之外支持火山引擎 TTS（代码中已有 `VOLCENGINE_API_KEY` 预留），提供更自然的语音质量。优先级：先优化默认的 edge-tts 语音选择（当前默认 `zh-CN-XiaoxiaoNeural`），让用户可以通过一个下拉菜单切换，但**默认值就够好**。

### 4.6 P2：视频动效微调

- Ken Burns 缩放从 1.08 调整到 1.12（仍然 subtle 但可感知）
- 淡入淡出根据段长动态调整：段长 < 5 秒时用 0.5 秒，≥ 5 秒时用 1 秒

## 5. 交互简化方案

### 核心设计思路

**从「7 步流水线」变为「2 步：输入 → 生成」**

不是删掉中间步骤，而是把它们**藏到后台自动执行**，用户只在需要干预时才看到细节。

### 5.1 新的主流程

```
┌─────────────────────────────────────────────────┐
│  [笔记编辑区]                                      │
│                                                  │
│  # 《思考快与慢》读书笔记                          │
│  丹尼尔·卡尼曼在书中提出了系统1和系统2...            │
│                                                  │
│  ┌──────────────────┐  ┌──────────────────┐      │
│  │  🎬 生成视频      │  │  📊 生成图文       │      │
│  └──────────────────┘  └──────────────────┘      │
│                   ↑ 两个大按钮，不展示中间步骤         │
└─────────────────────────────────────────────────┘
```

点击「生成视频」后：

1. 后端自动执行完整的 pipeline
2. 通过 SSE 推送进度：「正在理解你的笔记...」「正在优化脚本...」「正在生成第 3/8 张配图...」
3. 任何环节失败：自动重试一次，仍失败则用 fallback（文字卡片替代 AI 配图等），**继续生成不中断**
4. 完成后展示预览 + 下载按钮
5. 用户可点击「查看详情」展开看每一步的具体产出（进阶用户需求）

### 5.2 配置外置

所有参数选择（模型、风格、音色、分辨率）**不再在每次生成时选择**，而是放到一个全局「生成偏好」面板：

```
偏好设置（一次配置，全局生效）
├── 🎨 配图风格： [水墨中国风 ▼]
├── 🎤 TTS 语音： [知性女声 ▼]
├── 🎬 视频风格： [知识解读 ▼]  
├── 📐 分辨率：   [横屏 1920×1080 ▼]
└── 🤖 AI 模型：  [默认模型 ▼]
```

**首次使用时引导用户配置一次**，之后点击「生成视频」直接用这些默认值跑。

### 5.3 失效恢复策略

这是整个优化中最关键的部分——**让 pipeline 对失败有弹性**：

| 环节失败 | Fallback 策略 | 用户可见 |
|---------|--------------|---------|
| LLM 脚本解析失败 | 重试一次（换 model），仍失败则用简单分段（每段=原文段落） | 视频提示「脚本为自动分段，可手动优化」 |
| 配图生成失败 | 先用文字卡片（白底黑字显示段落关键句）替代，不中断流程 | 视频中该段无 AI 图但信息不缺失 |
| TTS 失败 | 用 edge-tts 默认语音重试，仍失败则生成无声视频浮字幕 | 「该段暂缺配音」 |
| 字幕生成失败 | 不中断，生成无字幕版本 | 「字幕生成失败，可手动重试」 |
| FFmpeg 合成失败 | 返回最后可用的中间产物（分段视频 zip） | 「合成失败，已导出为分段视频」 |

原则：**宁可出一支不完美的视频，也不出一支「生成失败，请重试」的提示**。

### 5.4 一键生成：真正的一键

将现有的 7 个独立 API 调用合并为一个 SSE 端点：

```
POST /api/notes/{id}/generate-video  (已存在，但只做 AI 视频)
    ↓
新增：POST /api/notes/{id}/auto-generate  (全链路一键)
    - 接受参数：无（全部使用用户预设）
    - 返回：SSE 流式推送进展 + 最终视频 URL
    - 故障：按 5.3 的 fallback 策略自动恢复
```

## 6. 成功指标

### 6.1 定量指标

| 指标 | 当前基线 | 目标 | 测量方式 |
|------|---------|------|---------|
| 生成成功率（无任一环节完全失败） | ~50% | ≥ 85% | 后端日志统计 |
| 生成完成率（用户启动后看到了最终视频） | ~60% | ≥ 90% | 前端埋点 |
| 平均生成时间（笔记→视频） | — | ≤ 3 分钟 | 后端计时 |
| 用户操作次数（从打开笔记到看视频） | ~15 次点击 | ≤ 5 次点击 | 前端埋点 |
| 配图「文字卡片」fallback 比例 | — | ≤ 15% | 数据库统计 |

### 6.2 定性指标

- 5 人内部测试：能否不读任何文档就完成一次视频生成？目标：5/5 成功
- 对比测试：同样的笔记，旧版 vs 新版生成的视频，盲测打分（1-5 分），新版 ≥ 4.0

## 7. 实施计划

### Phase 1：救命（1 周）

修复导致生成彻底失败的 bug + 最影响观看体验的问题：

1. 脚本解析从 JSON 改为 Markdown 结构（P0）
2. 字幕加半透明背景条（P0）
3. 配图 prompt 合并到脚本生成一步（P0）
4. 失效恢复策略实现（P0：所有 fallback 逻辑）

### Phase 2：变好（1 周）

提升默认输出质量 + 简化交互：

1. 图片风格扩展（P1：新增 5 种风格）
2. 「生成偏好」面板 + 默认值记忆（交互核心）
3. 两步主流程 UI 改造（交互核心）
4. 自动生成一键 SSE 端点（交互核心）

### Phase 3：打磨（1 周）

锦上添花：

1. TTS 引擎扩展（火山引擎）（P1）
2. Ken Burns / 淡入淡出微调（P2）
3. 初次使用引导（新手引导弹窗）
